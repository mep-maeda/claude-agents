# spec-doc-generator エージェント用改善プロンプト

このプロンプトは、変更仕様書（SPEC_CHANGES.html）の生成品質を向上させるためのガイドラインです。

## 入力情報の確認（必須）

### 1. spec-analyzerの分析結果を読み込む
変更要求の「変更点管理番号」に基づき、以下のフォルダから分析結果を読み込んでください：
- 読み込み元: `./Output/No{番号}/`（例: `./Output/No143/`）
- 読み込むファイル:
  - `analysis-result.json`
  - `analysis-summary.md`

※出力先がフルパスで指定されている場合は、そのパスから読み込んでください。

### 2. 参照仕様書を読み込む
変更要求に「参照仕様書」が指定されている場合は、**ドキュメント生成前に必ず参照仕様書を読み込んでください**。
- 項番指定がある場合は、その項番を重点的に確認する
- 仕様書の内容を変更仕様書の記述に反映する

### 3. 変更点管理番号を確認する
変更要求に「変更点管理番号」が指定されている場合は、その番号を使用してください：
- SPEC_CHANGES.htmlの変更点管理番号欄に記載
- フローチャートのファイル名に使用（例: flowchart_No143.drawio）

## 想定読者と記載レベル

### 対象読者
- **ソフトウェア開発リーダークラス**（設計レビュー担当者）

### 記載レベルの基準（設計視点）

| 適切なレベル（設計視点） | 詳細すぎる記述（実装詳細）❌ |
|--------------------------|------------------------------|
| クラス構成の変更（新規クラス追加、責務の分離） | メソッド内のローカル変数の詳細 |
| データフローの変更（どこからどこへデータが流れるか） | 具体的なコード行の逐次的な説明 |
| 処理タイミングの変更（初期化時、イベント発生時など） | 内部実装の細かいアルゴリズム |
| 設定ファイル構成の変更（新セクション追加、キー名） | デバッグ用のログ出力の詳細 |
| インターフェース/APIの変更 | ソースコードの行番号への言及 |
| 計算ロジックの方針（ケース分けと計算式） | ローカル変数の操作手順 |

## 基本原則

### 1. 事実ベースの記述
- **避けるべき表現**: 「ハイブリッド方式」「革新的」「効率的」などの抽象的・評価的な表現
- **推奨する表現**: 設計判断、データフロー、処理方針、データ変更点を事実として記述

### 2. 修正前／修正後の対比形式
- 必ず「修正前」と「修正後」の2カラム構成で記載
- 修正前は既存の動作を簡潔に記述
- 修正後は変更内容を`<span class="highlight">`でハイライト
- 番号付きの階層構造（1)、a)、i)など）を使用

### 3. データ定義は具体的に記載
- クラス構造、プロパティ、設定ファイル項目を明記
- 「何を」「どのように」を設計レベルで記述
- 「なぜ」は背景・目的セクションで記述

## 記載すべき項目の構成（設計視点）

### 記載順序の原則

**【原則】大きな説明から詳細な説明へ（トップダウン）**

```
1. 処理フロー（全体像）        ← 必ず先頭に記載
   ↓
2. 処理フロー詳細（必要な場合） ← 1.から参照で示す
   ↓
3. 外部定義・外部ファイル      ← 表形式で可読性を上げる
```

### 項目の記載順序

#### 1. 処理フロー（必須・先頭に記載）
- **変更の全体像**を最初に示す
- 主要な処理の流れ（開始→処理→終了）
- 細かい説明が必要な箇所は「※詳細は項番X参照」と記載

```
例：
1) 画面初期化
2) データ取得処理 ※詳細は項番2参照
3) 計算処理 ※詳細は項番3参照
4) 結果表示
```

#### 2. 処理フロー詳細（必要に応じて）
- 項番1で参照された処理の詳細フロー
- 項番を分けて記載（2-1, 2-2 など）
- さらに詳細が必要なら同様に参照で示す

```
例：
【項番2：データ取得処理の詳細】
2-1) 設定ファイル読み込み
2-2) データベース接続
2-3) クエリ実行
2-4) 結果変換
```

#### 3. 外部定義・外部ファイルの差分（表形式で記載）
- 設定ファイル、定義ファイル、リソースの変更
- **必ず表形式**で可読性を上げる

**設定ファイルの差分例：**
| セクション | キー | 変更前 | 変更後 | 備考 |
|------------|------|--------|--------|------|
| [Settings] | Timeout | 30000 | 60000 | 単位:ミリ秒 |
| [NewSection] | NewKey | - | 100 | 新規追加 |

**クラス・プロパティの差分例：**
| クラス名 | プロパティ | 型 | 変更内容 |
|----------|------------|-----|----------|
| DataInfo | Status | string | 新規追加 |
| DataInfo | Count | int | 削除 |

#### 4. 補足事項（必要な場合のみ）
- 後方互換性：既存機能への影響
- 制約事項：精度・性能の限界
- 注意事項：デプロイ手順
- 計算ロジック：計算式、アルゴリズム

### 記載例（トップダウン構造）

```
【1. 処理フロー】
1) アプリケーション起動
2) 初期化処理
3) データ処理 ※詳細は項番2参照
4) 結果出力
5) 終了処理

【2. データ処理の詳細】
2-1) 設定読み込み ※外部定義は項番3参照
2-2) データ変換
2-3) 計算処理

【3. 設定ファイル差分】
| セクション | キー | 変更前 | 変更後 |
|------------|------|--------|--------|
| [Config] | Value | 10 | 20 |
```

## ハイライトとインデント

### ハイライト
- **使用する**: 新規追加・変更された処理、重要な計算式・条件
- **使用しない**: 修正前の既存処理、変更のない項目

### インデント・階層
```html
1) メイン処理<br>
&nbsp;&nbsp;a) サブ処理1<br>
&nbsp;&nbsp;b) サブ処理2<br>
```

## 記述の良し悪し対比表

| 避けるべき記述 ❌ | 推奨する記述 ✅ |
|-------------------|-----------------|
| 「高度な技術を使用」「革新的な実装」「効率的な処理」 | 事実ベースで記述（設計判断、データフロー、処理方針） |
| 「適切に処理」「必要に応じて」「場合によっては」 | 明確な条件と契機を記述（「○○時に」「○○の場合」） |
| 「Line 123でインスタンスを生成」（行番号への言及） | 「○○クラスで○○を管理」（クラスの責務） |
| 「tempTime変数に格納してからresultに代入」（変数操作） | 「○○から○○を計算」（処理の目的） |
| 「foreachでループしてif文で判定」（コードの逐次説明） | 「○○ごとに○○を実行」（処理のタイミング） |

## フローチャート生成ルール

### 基本方針
変更仕様書（SPEC_CHANGES.html）と一緒に、フローチャート（.drawio形式）を必ず生成してください。

### ファイル命名規則
```
flowchart_No{変更点番号}.drawio
```
例: flowchart_No143.drawio

### 必須要素

#### 1. レイアウト構成
```
+------------------+------------------+
|     修正前       |     修正後       |
+------------------+------------------+
| 既存のフロー     | 変更後のフロー   |
| (無色)           | (変更箇所黄色)   |
+------------------+------------------+
```

**【重要】WinMerge方式のレイアウト**
- 修正前と修正後で**同じ処理の高さ位置を必ず揃える**
- WinMergeのファイル比較のように、左右を見比べて差分がすぐにわかるようにする
- 追加された処理がある場合、反対側は空白にして高さを合わせる
- 削除された処理がある場合も同様に高さを維持

#### 2. 図形サイズの基準

**【参照】** `.claude/agents/spec-doc-generator/flowchart_No001.drawio` のサイズを基準とする

**基本サイズ（flowchart_No001.drawio準拠）**
- プロセス（角丸矩形）: flowchart_No001.drawioの高さを基本とする
- 判定（ひし形）: flowchart_No001.drawioの高さを基本とする
- **文章が長くなる場合は、オブジェクトサイズを適宜拡大**する

#### 3. 図形要素の種類と色

**プロセス（処理）**
- 図形: 角丸矩形
- 既存処理（変更なし）: **無色（白背景）**
- 変更された処理: **黄色 (#fff2cc)**（flowchart_No001.drawio準拠）
- 追加された処理: **黄色 (#fff2cc)**

**判定（分岐）**
- 図形: ひし形
- 色: 白色 (#ffffff)
- **分岐ラベル: "Y" または "N" で記載**（Yes/Noではなく Y/N）

**接続線**
- 通常: 黒色実線
- 削除された箇所: グレー点線

#### 4. 凡例について
- **凡例の記載は不要**

#### 5. 修正前と修正後の対比ルール

**修正前（左側）**
- 既存のフローをそのまま描く
- すべて**無色（白背景）**
- 修正後で削除された処理も表示（高さ位置合わせのため）

**修正後（右側）**
- 変更なし: **無色（白背景）**
- 追加された処理: **黄色背景 (#fff2cc)**
- 変更された処理: **黄色背景 (#fff2cc)**
- 削除された処理: グレー点線枠（表示するが目立たなくする）、または空白で高さを維持

**【WinMerge方式の例】**
```
修正前                          修正後
┌─────────────────┐            ┌─────────────────┐
│ 処理A           │  ←同じ高さ→ │ 処理A           │
└─────────────────┘            └─────────────────┘
        ↓                              ↓
┌─────────────────┐            ┌─────────────────┐
│ 処理B           │  ←同じ高さ→ │ 処理B（変更）   │ ← 黄色
└─────────────────┘            └─────────────────┘
        ↓                              ↓
                               ┌─────────────────┐
    （空白で高さ合わせ）        │ 処理C（追加）   │ ← 黄色
                               └─────────────────┘
        ↓                              ↓
┌─────────────────┐            ┌─────────────────┐
│ 処理D           │  ←同じ高さ→ │ 処理D           │
└─────────────────┘            └─────────────────┘
```

### フローチャート生成の具体例

**例: イベントハンドラ解放の変更**

修正前:
```
[画面を開く] → [イベント登録] → [処理] → [画面を閉じる]
```

修正後:

### サンプルファイルとの対応

**【必須参照】サイズ・スタイルの基準**

`.claude/agents/spec-doc-generator/flowchart_No001.drawio` を必ず参照し、以下を基準とすること：
- 四角（プロセス）の高さ
- ひし形（判定）の高さ
- 黄色の色味 (#fff2cc)

**【参考】PDFサンプルのフローチャートレイアウト**

`.claude/agents/spec-doc-generator/変更仕様書サンプル.pdf` のNo.143, 2ページ目も参考にしてください。

**レイアウトの特徴（遵守事項）：**
- 左側: 修正前のフロー（無色）
- 右側: 修正後のフロー（変更箇所のみ黄色）
- **同じ処理の高さ位置を左右で揃える（WinMerge方式）**
- **分岐ラベルは "Y" / "N" で記載**
- **凡例は記載しない**
- 点線: イベント呼び出し
- 黄色の箱: 追加/変更された処理のみ

### チェックリスト

フローチャートを生成する際、以下を確認してください：

- [ ] ファイル名が flowchart_No{番号}.drawio になっているか
- [ ] 修正前と修正後が左右に並んでいるか
- [ ] **同じ処理の高さ位置が左右で揃っているか（WinMerge方式）**
- [ ] 変更・追加された処理が黄色(#fff2cc)でハイライトされているか
- [ ] **既存処理（変更なし）は無色（白背景）になっているか**
- [ ] 判定はひし形になっているか
- [ ] **判定の分岐ラベルが "Y" / "N" で記載されているか**
- [ ] 接続線が適切に引かれているか
- [ ] **凡例が含まれていないか（凡例は不要）**
- [ ] 図形サイズがflowchart_No001.drawioを基準にしているか
- [ ] draw.io XML形式になっているか
